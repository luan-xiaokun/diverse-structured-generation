# Phase 01.1: Repair tokenizer vocabulary and byte-DFA contract - Context

**Gathered:** 2026-07-24
**Status:** Ready for planning

<domain>
## Phase Boundary

Repair the token-vocabulary/byte-DFA boundary so every tokenizer token is represented and traversed by its exact bytes, then make that contract durable across the public API, serialized artifacts, tests, and baseline witness diagnostics. This phase also prevents obligations that are provably unreachable under the repaired byte-level contract from consuming witness-generation slots.

This phase does not add multi-obligation witness generation, LLM-guided naturalness, suite minimization, or case-study evaluation. Those remain downstream work.

</domain>

<decisions>
## Implementation Decisions

### Vocabulary API contract
- **D-01:** Make the public vocabulary contract breaking and bytes-only. `DiverseGuideDFA` accepts `dict[int, bytes]`; it does not accept `str | bytes`.
- **D-02:** Change the existing `build_token_id_map()` contract to return exact token bytes. Do not retain a parallel legacy string-map API.
- **D-03:** Passing any `str` vocabulary value must fail immediately with an actionable `TypeError`. Do not auto-encode, warn-and-continue, or provide a compatibility path.
- **D-04:** Bump both the parent Python package and `regex_dfa_guide` package to version `0.3.0` to mark the breaking API and artifact contract.

### Serialized artifact boundary
- **D-05:** The new artifact format must start with an explicit magic header and carry an artifact schema version independent of the package version.
- **D-06:** Artifacts must be self-contained. Persist the exact raw vocabulary bytes together with DFA/token indexes, paths, and counters so restore requires neither the tokenizer nor network access.
- **D-07:** Reject old artifacts strictly. Loading must distinguish `legacy_artifact` (no new magic), `unsupported_schema`, and `corrupt_artifact`; there is no automatic migration or backward-compatible decoder.
- **D-08:** Guarantee behavioral round-trip equivalence, not byte-for-byte identical serialization from independent builds.

### Byte-contract verification
- **D-09:** Require both hermetic synthetic contract tests and a real integration test using the locked Qwen tokenizer revision.
- **D-10:** For any encoded source text, require
  `concat(vocabulary_bytes[token_id] for token_id in token_ids) == source_text.encode("utf-8")`.
- **D-11:** Token-driven traversal must exactly match direct byte traversal of the source text: acceptance, ordered states, byte transitions, and state-pair paths must all agree. Final-state-only parity is insufficient.
- **D-12:** Synthetic tests must cover ASCII, a complete Unicode token, a Unicode code point split across multiple BPE fragments, a token mixing ASCII with incomplete high bytes, Llama-style `<0xNN>`, a true U+FFFD token distinct from a byte fragment, and EOS as a zero-byte action.
- **D-13:** Keep ordinary CI hermetic and synthetic. Run locked Qwen/CSS parity in a separate job with `HF_HUB_OFFLINE=1`; a missing snapshot must fail with the lock key and revision in the error. Do not skip, xfail, or fall back to the network.

### Unreachable-obligation diagnostics
- **D-14:** Preserve the project definition of a coverage obligation: it is only a DFA state, transition, or path that the selected baseline samples did not visit. Already-covered DFA structures are not obligations.
- **D-15:** Before witness search, test whether an uncovered obligation can lie on a sequence that starts at the DFA initial state and ends at an accepting state under the repaired bytes contract. If no such sequence exists, diagnose it as machine category `byte_level_unreachable`.
- **D-16:** A byte-level-unreachable item remains an uncovered obligation and remains visible in aggregate coverage and diagnostics. It is not reclassified out of the obligation set.
- **D-17:** `--sample-num` determines which baseline samples are used to compute the uncovered obligations. After byte-level reachability classification, `--obligation-num N` selects up to `N` obligations only from the reachable remainder. Unreachable obligations do not consume witness-generation slots.
- **D-18:** Use mutually exclusive outcome categories: `success`, `byte_level_unreachable`, `search_limit`, `invalid_witness`, and `internal_error`. Do not report the ambiguous generic failure “no accepting state.”
- **D-19:** Each structured result must identify the obligation type and stable ID and include the category, reachability evidence or failure reason, and applicable search budget.
- **D-20:** Put all `byte_level_unreachable` obligation diagnostics in the aggregate `--json` result and show category counts in terminal output.
- **D-21:** Keep `--jsonl` strictly limited to certificates for obligations that actually entered witness generation. It may contain `success`, `search_limit`, `invalid_witness`, and `internal_error` certificates, but neither baseline samples nor unselected unreachable-obligation diagnostics.

### the agent's Discretion
- Exact magic-header bytes, schema-number encoding, and serialization library, provided the artifact behaviors above are enforced.
- Exact graph/reachability algorithm and evidence representation used to prove `byte_level_unreachable`.
- Deterministic tie-breaking among reachable obligations and concrete search-budget defaults, provided they preserve the locked `--sample-num` and `--obligation-num` semantics.
- Test-fixture organization and CI job naming.

</decisions>

<code_context>
## Existing Code Insights

### Reusable Assets
- `src/diverse_guide/vocab.py`: Existing GPT-2 byte/unicode inverse mapping and raw-token inspection are the natural foundation for recovering exact bytes without decoding incomplete UTF-8 fragments.
- `DiverseGuideDFA` trace APIs: Existing state, transition, state-pair path, acceptance, and counter outputs can serve as the two sides of exact direct-text versus token-driven parity checks.
- AIAP replay/certificate pipeline: Existing aggregate JSON and per-proposal JSONL outputs provide the integration points for reachability diagnostics and explicit witness outcomes.

### Established Patterns
- The locked tokenizer revision is part of experiment identity; the real parity check must use the exact Qwen revision and run offline.
- Witness claims are replay-verified. Generated text alone is not sufficient evidence of acceptance or coverage.
- Runs are deterministic and auditable; failures and exclusions must remain structured rather than disappearing from output.

### Integration Points
- Replace sentinel `str` fragments at vocabulary construction, then propagate `bytes` through both Python guides, the Python/Rust binding, Rust storage, and token traversal.
- Replace Rust `HashMap<TokenId, String>` storage and string `.as_bytes()` traversal with an exact byte-vector representation.
- Wrap serialized DFA state in the new magic/schema envelope and preserve all data necessary for tokenizer-free restore.
- Classify missing obligations before AIAP target selection, then route unreachable diagnostics to aggregate JSON and selected generation outcomes to witness JSONL.

</code_context>

<specifics>
## Specific Ideas

- The motivating failure is a Qwen/CSS case where tokenizer fragments representing high UTF-8 bytes were converted to sentinel strings such as `"\x00E1\x009A"`. Rust then traversed the sentinel string's bytes (`00 45 31 ...`) rather than the intended bytes (`E1 9A ...`), making valid Unicode whitespace branches appear impossible to complete.
- The bytes-only API is intentionally clean and breaking. The user explicitly rejected compatibility handling because old artifacts have little practical value and silent conversion would weaken the contract.
- “Byte-level unreachable” is a feasibility diagnosis, not a synonym for a bounded search failure.

</specifics>
