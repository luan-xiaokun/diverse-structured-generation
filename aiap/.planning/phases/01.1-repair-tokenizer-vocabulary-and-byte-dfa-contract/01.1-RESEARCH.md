## Summary

The defect is not a Unicode-regex defect. The Python vocabulary layer turns incomplete UTF-8 token fragments into sentinel strings such as `"\x00E1\x009A"`, and Rust subsequently walks the UTF-8 bytes of that sentinel string rather than the intended raw bytes. In the locked Qwen snapshot, token `124999` is raw `E1 9A`, token `222` is raw `80`, and together they encode U+1680. Direct CSS traversal accepts a source containing U+1680, while current token traversal fails at token `124999`. The snapshot contains 1,456 one-token decodes with replacement characters, so a final-state-only or ordinary-sample-only test cannot guard this boundary. [VERIFIED: local `../src/diverse_guide/vocab.py`, locked Qwen probe, and `../regex_dfa_guide/src/diverse_guide_dfa.rs`]

The correct repair is a single bytes-only path: recover `bytes` in `build_token_id_map`, manually require Python `bytes` at the PyO3 constructor, store `Vec<u8>` in `DfaIndex`, iterate those bytes directly, and serialize the same byte vectors. Merely changing the Rust argument to `HashMap<u64, Vec<u8>>` is insufficient because PyO3's generic `Vec<T>` extractor also accepts other Python sequences; manual `PyDict`/`PyBytes` validation is required for D-01/D-03. [VERIFIED: local PyO3 0.28.3 source `conversions/std/vec.rs:65-110`; CITED: https://pyo3.rs/main/doc/pyo3/types/struct.PyBytes]

Reachability should be computed on the tokenizer-action graph annotated with each action's repaired byte trace, not inferred from a failed bounded witness search and not computed over the entire DFA catalog. First derive uncovered obligations from the selected baseline certificates; then use forward reachability from the initial state plus reverse co-reachability to a final state, crediting the interior byte states/transitions/paths of qualifying token actions. This proves that a classified-reachable obligation can occur on an accepting token sequence and cleanly separates `byte_level_unreachable` from `search_limit`. [VERIFIED: local `aiap/aiap/cli.py`, `aiap/aiap/obligations.py`, `aiap/aiap/baseline.py`, and phase decisions D-14 through D-18]

**Primary recommendation:** implement four ordered slices: (1) bytes-only vocabulary/binding/version contract, (2) strict self-contained artifact envelope, (3) annotated token-graph reachability and typed outcomes, and (4) synthetic plus locked offline trace-parity gates. [VERIFIED: phase decisions D-01 through D-21 and affected-code audit]

### Pattern 1: Exact token-byte recovery

Use one conversion function that returns bytes directly:

1. Raw token object is `bytes` → copy it unchanged.
2. Raw token matches `<0xNN>` → one byte with value `NN`.
3. One-token decoded text contains U+FFFD and the raw token is not itself the replacement sequence → invert every GPT-2 visible byte symbol in the raw token.
4. Otherwise → UTF-8 encode the one-token decoded text.
5. Exclude EOS/special tokens as today; EOS remains a Rust token-level zero-byte action.

This preserves the existing supported tokenizer-family branches without ever creating a sentinel string. It reproduced exact source bytes for all 1,000 locked CSS samples and all 1,000 locked email samples in the research probe. [VERIFIED: local reconstruction probe; CITED: https://huggingface.co/docs/tokenizers/python/latest/components.html; CITED: https://github.com/QwenLM/Qwen/blob/main/tokenization_note.md]

```python
# Source pattern: ../src/diverse_guide/vocab.py plus official ByteLevel/Qwen docs
def token_to_bytes(tokenizer, token: str | bytes, token_id: int) -> bytes:
    if isinstance(token, bytes):
        return bytes(token)
    if RE_LLAMA_BYTE_TOKEN.fullmatch(token):
        return bytes([int(token[3:5], 16)])

    decoded = tokenizer.convert_tokens_to_string([token])
    if "\ufffd" in decoded and not RE_REPLACEMENT_SEQ.fullmatch(token):
        values = [gpt2_unicode_to_bytes().get(char) for char in token]
        if any(value is None for value in values):
            raise RuntimeError(
                f"Cannot recover exact bytes for token {token!r} ({token_id})"
            )
        return bytes(values)
    return decoded.encode("utf-8")
```

### Pattern 2: Strict Python boundary, not permissive sequence extraction

Accept a `PyDict`, extract integer keys, require each value to cast to `PyBytes`, and include the offending token ID/type in the `TypeError`. Then convert `PyBytes::as_bytes()` to `Vec<u8>`. Do not accept `bytearray`, `list[int]`, or `str`. [VERIFIED: D-01/D-03 and local PyO3 extraction behavior]

The binding must validate vocabulary values before calling DFA construction so the user receives the contract error directly rather than a regex or transition error. [VERIFIED: current `__new__` call order and D-03]

### Pattern 3: Explicit artifact envelope

Use a fixed eight-byte magic, an independent little-endian `u16` schema, then the existing bincode payload. Recommended constants:

```rust
const ARTIFACT_MAGIC: &[u8; 8] = b"RDGDFA\0\0";
const ARTIFACT_SCHEMA_VERSION: u16 = 1;
```

Load in this exact order:

1. Missing/wrong magic → `legacy_artifact`.
2. Magic present but incomplete schema field/payload → `corrupt_artifact`.
3. Schema not equal to 1 → `unsupported_schema`.
4. Decode failure or decoded-byte count not equal to payload length → `corrupt_artifact`.

`bincode::decode_from_slice` returns the consumed-byte count, so trailing garbage must be checked explicitly; the current binding ignores that count. [VERIFIED: `../regex_dfa_guide/src/python_bindings/mod.rs:190-197`; CITED: https://docs.rs/bincode/2.0.1/bincode/fn.decode_from_slice.html]

Keep `DfaIndex`, vocabulary bytes, token transitions, token state paths, allowed IDs, path counters, and local counters in the payload. No tokenizer identity or regex reconstruction is required for restore because the compiled behavioral index is already persisted. [VERIFIED: `../regex_dfa_guide/src/diverse_guide_dfa.rs:20-32,401-447`]

### Pattern 4: Annotated token-graph reachability

Build the graph once per DFA:

- Forward BFS from `get_initial_state()` over sorted allowed token IDs.
- For each token action, record destination plus `get_byte_transition_sequence_from_state(source, token_id)[1:]`.
- Reverse BFS from final states over the recorded token edges.
- A token action is on an accepting token trace exactly when its source is forward-reachable and its destination is final-co-reachable.
- Credit the action's source/interior states, exact `(source, byte, target)` transitions, and ordered `(source, target)` paths as reachable obligations.
- Classify only the already-derived missing-obligation list; do not emit records for covered catalog entries.

[VERIFIED: available DFA APIs and D-14/D-15; algorithm is the recommended use of the agent's discretion]

Reachability evidence should use a stable schema such as:

```python
{
    "algorithm": "annotated_token_graph_v1",
    "forward_state_count": 12,
    "coreachable_state_count": 11,
    "matching_accepting_action_count": 0,
}
```

For reachable attempted obligations, retain the matching action/token and prefix/suffix lengths or predecessor IDs; for unreachable obligations, `matching_accepting_action_count == 0` is the negative proof. [VERIFIED: D-19; evidence shape is a recommended implementation choice]

### Pattern 5: Outcome is separate from low-level replay failure

Keep replay diagnostics such as `illegal_token`, `byte_trace`, or `destination_mismatch` as detailed causes, but map each selected proposal to exactly one top-level outcome:

| Condition | Outcome |
|---|---|
| Classifier proves no accepting token trace can cover missing item | `byte_level_unreachable` |
| Search exhausts its explicit cap before finding a candidate | `search_limit` |
| Search returns tokens but replay rejects them or does not cover the target ID | `invalid_witness` |
| Replay accepts and covers the target ID | `success` |
| Unexpected exception/invariant break | `internal_error` |

[VERIFIED: D-18 and current replay failure categories]

Use a shared structured target/result record containing obligation ID, kind, raw meaning, outcome, reachability evidence or failure reason, and search budget. Embed the attempted form in each JSONL certificate; serialize unreachable forms only in aggregate JSON. [VERIFIED: D-19 through D-21]

### Required pipeline ordering

```text
slice samples by --sample-num
→ replay selected samples
→ derive missing obligations
→ classify every missing obligation
→ retain every unreachable diagnostic for aggregate JSON
→ select first N reachable items in stable catalog order
→ search/replay only selected reachable items

```

### Anti-Patterns to Avoid

- **Decoded-token text as vocabulary truth:** one-token decoding replaces incomplete UTF-8; use raw token bytes/inverse mapping. [CITED: https://github.com/QwenLM/Qwen/blob/main/tokenization_note.md]
- **`HashMap<u64, Vec<u8>>` alone as validation:** it still permits non-bytes sequences. [VERIFIED: local PyO3 0.28.3 source]
- **Running reachability over the full catalog:** covered structures would incorrectly become obligation diagnostics. [VERIFIED: D-14]
- **Raw byte-graph-only feasibility:** it does not prove tokenizer-action feasibility. [VERIFIED: distinct `byte_transitions` and pruned `token_transitions` in `DfaIndex`]
- **Using BFS `None` as unreachable proof:** a bounded/capped search failure is not a graph infeasibility proof. [VERIFIED: D-15/D-18 and current `construct_one_witness` return type]
- **Slicing before reachability classification:** unreachable items would consume `--obligation-num`. [VERIFIED: current incorrect `cli.py:126-134` versus D-17]
- **Nondeterministic token iteration:** `allowed_token_ids` originates from a Rust hash set; sort token IDs before BFS/tie-breaking. [VERIFIED: `DfaIndex::new` lines 123-163]
- **Ignoring consumed bytes on artifact decode:** valid payload plus trailing bytes would be accepted as if intact. [VERIFIED: current binding line 191 ignores the second tuple element]
- **Testing only acceptance:** ordered state/transition/path mismatches would remain invisible. [VERIFIED: D-11]

## Common Pitfalls

### Pitfall 1: Complete Unicode tests pass while fragment tokens remain broken

**What goes wrong:** tokens representing a complete UTF-8 character decode correctly, hiding incomplete-fragment corruption.  
**Why it happens:** the current code only takes the inverse-byte branch when one-token decode contains U+FFFD.  
**How to avoid:** include U+1680 split into locked Qwen tokens `124999` (`E1 9A`) and `222` (`80`), plus mixed ASCII/incomplete-byte synthetic cases.  
**Warning signs:** D-10 passes for ordinary ASCII/CSS samples but `get_next_token_state` rejects token `124999` on a direct-byte-valid path.  
[VERIFIED: locked Qwen probe and current code]

### Pitfall 2: Conflating genuine U+FFFD with a decode replacement

**What goes wrong:** a real replacement-character token is reconstructed as unrelated incomplete bytes, or an incomplete fragment becomes UTF-8 `EF BF BD`.  
**How to avoid:** test raw genuine replacement form and incomplete fragment separately; only use the inverse map when raw-token evidence identifies byte-level symbols.  
[VERIFIED: existing `RE_REPLACEMENT_SEQ` intent and D-12]

### Pitfall 3: Rebuilding too late

**What goes wrong:** Python tests exercise the old shared object and report missing methods or old types even though Rust source is correct.  
**How to avoid:** make extension rebuild the Wave 0 boundary after Rust/binding edits and before all Python integration tests.  
**Warning signs:** `regex_dfa_guide.__version__` or import metadata remains 0.2.0.  
[VERIFIED: local environment/test probe]

### Pitfall 4: Reachability classifier uses pruned outputs without proving both sides

**What goes wrong:** an interior byte edge is marked reachable merely because it appears in some token path, without a prefix from initial or suffix to final.  
**How to avoid:** explicitly compute forward and reverse sets and only inspect qualifying actions.  
[VERIFIED: D-15]

### Pitfall 5: Successful acceptance does not cover the requested target

**What goes wrong:** search returns an accepted witness but target matching was predicted incorrectly.  
**How to avoid:** `success` requires both `certificate.accepted` and target ID in `covered_obligation_ids`; otherwise use `invalid_witness`.  
[VERIFIED: project correctness constraint and D-18]

### Pitfall 6: JSON and JSONL populations drift

**What goes wrong:** baseline certificates or unreachable/unselected diagnostics leak into JSONL, or unreachable obligations disappear from aggregate JSON.  
**How to avoid:** construct `attempt_certificates` as a separate collection at the moment reachable selected items enter search; JSONL writes only that collection.  
[VERIFIED: D-20/D-21 and current metadata-filter implementation]

### Pitfall 7: Artifact schema is accidentally tied to package version

**What goes wrong:** a package patch release changes load behavior or schema 1 artifacts are rejected based on package version.  
**How to avoid:** keep `ARTIFACT_SCHEMA_VERSION` independent of the package's 0.3.0 version and dispatch only on the header schema field.  
[VERIFIED: D-04/D-05]
